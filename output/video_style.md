# Стиль генерации видео «ЕГЭ Тренажёр» (на будущее)

Параметры для фото-части (0–6 сек), поверх основного ТЗ из `ЕГЭ Тренажёр формат видео ТЗ.pdf`:

- **line_spacing (интервал между строк): 4px** — было 12–14, сделано теснее по просьбе
- **shadowcolor + bordercolor/borderw: ADAPTIVE** — тень и обводка текста подбираются автоматически под каждое фото, см. раздел ниже
- **shadowx/shadowy: 4**
- **fontcolor:** white, **text_align:** C+M (центр по обеим осям)
- **fontfile:** /usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf
- **fontsize:** подбирается так, чтобы хук помещался в ≤4 строки при ширине ≤920px (обычно 64, для длинных хуков — меньше, напр. 48)
- **alpha (fade-in):** `if(lt(t,0.5),0,if(lt(t,0.9),(t-0.5)/0.4,1))` — появление с 0.5 по 0.9 сек

## Фикс дрожания (jitter) при zoompan

Проблема: если применять `zoompan` сразу на кадре 1080×1920, он считает крop-окно в целых пикселях этого маленького разрешения — шаг зума в 1px даёт заметный скачок/тряску, особенно в начале ролика (зум около 1.0).

Фикс — перед `zoompan` кадр дополнительно апскейлится в 4 раза (lanczos), чтобы у zoompan был запас в пикселях для плавного дробного зума:

```
scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,
scale=4320:7680:flags=lanczos,
zoompan=z='1+0.08*on/359':x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':d=360:s=1080x1920:fps=60,
...
```

Также вход с фото задаётся как `-loop 1 -framerate 60 -i photo.jpg` (явный framerate 60, а не дефолтный), чтобы кадры на входе в zoompan шли ровно, без рваного даплицирования.

## Адаптивная тень + обводка текста

Скрипт `scripts/shadow_analyze.py` перед рендером каждого сегмента оценивает
конкретное фото и подбирает параметры индивидуально, вместо фиксированных
значений на все ролики:

1. Повторяет crop-to-fill ffmpeg (scale под покрытие 1080×1920 + центр-кроп),
   чтобы анализировать именно то, что попадёт в кадр.
2. Берёт центральную область ~1000×820px — там, где будет сидеть текстовый блок.
3. Считает **среднюю яркость** (светлый/пёстрый фон — белый текст на нём
   сливается сильнее, нужна тень темнее) и **«шумность»** — среднюю величину
   градиентов/краёв в этой области (много мелких деталей под текстом снижает
   читаемость независимо от яркости).
4. Комбинирует в скор `0.55*яркость + 0.45*шумность` и мэпит в:
   - **shadow_alpha ∈ [0.35, 0.70]** — обычная тень со смещением (glубина)
   - **border_alpha ∈ [0.55, 0.90]**, **borderw ∈ [3, 6]px** — чёрная обводка
     по всему контуру букв (drawtext `bordercolor`/`borderw`)

Первая версия (только offset-тень, диапазон 0.12–0.50) оказалась
недостаточной: тень со смещением затемняет только один край буквы, поэтому
на ярких/пёстрых фото противоположный край оставался нечитаемым. Обводка со
всех сторон решает это — текст читается независимо от фона, а offset-тень
поверх даёт лёгкую глубину.

Использование:
```
python3 scripts/shadow_analyze.py IMG_XXXX.jpeg
# -> IMG_XXXX.jpeg: brightness=... busyness=... score=... -> shadow_alpha=0.NN border_alpha=0.NN borderw=N
```

Значения подставляются в `shadowcolor=black@<shadow_alpha>:shadowx=4:shadowy=4:
bordercolor=black@<border_alpha>:borderw=<borderw>` в команде ffmpeg для
конкретного сегмента.

## Музыка (с видео 14)

Пользователь прислал 5 аудиодорожек (извлечены из скринкастов, лежат в
`output/audio/track1..5.m4a`, AAC 44.1kHz stereo). Правило:

1. На каждое видео случайно (с повторами) выбирается один из 5 треков.
2. Трек **полностью заменяет** родной звук ролика (100% громкость, без подмешивания
   аудио из аутро-видео).
3. Итоговая длительность ролика = **min(длительность видео ~15.02с, длительность трека)**:
   - трек короче видео → обрезается видео (конец аутро укорачивается)
   - трек длиннее видео → обрезается сам трек

Технически: сначала рендерится обычное фото+аутро видео (как раньше, со своим
родным/тихим звуком), затем финальным проходом видео-дорожка берётся из него,
а аудио-дорожка — из выбранного трека, и всё обрезается общим `-t <target>`
(`target = min(video_dur, audio_dur)`), с полным перекодированием видео
(нужно для точной покадровой обрезки — `-c:v copy` округляет до ближайшего
ключевого кадра и даёт неточную длину). Реализовано в `scripts/mux_music.sh`
(читает `music_assign.tsv` вида `<idx>\t<номер_трека>`).
